# 「我们」v2 开发、构建与发布手册

给维护者和协作 AI：开始修改前先读取 `AGENTS.md` 和本文，执行 `git fetch origin main`，确认基于最新代码。不要直接修改服务器文件来代替提交和发布。

本文既说明现有实现，也规定后续改动的边界。标为“当前”的内容是代码现状；“扩展规则”是接手开发时必须遵守的约束，不能据此声称某项新功能已经实现。若代码与本文不一致，先定位对应实现和测试，再同时修正文档与代码；不得凭文档猜测接口或删除不理解的兼容逻辑。

阅读顺序：先看“模块边界与依赖方向”“业务模块定义”，再按改动类型阅读“后续扩展流程”和“测试与交付约束”；运行、测试、发布的实际命令在后半部分。

## 技术与目录

- `frontend/src/features/`：真实 Vue 3 单文件组件。按记录、约定、愿望积分、故事、回看、设置划分。各功能的编辑器在相应子目录中。
- `frontend/src/components/`：公共页面标题、弹层、图标。图标 SVG 来自既有设计，所有用户文本通过 Vue 插值转义。
- `frontend/src/stores/space.ts`：Pinia 管理空间快照、操作队列及会话协调。页面不要直接调用 `fetch` 或写服务器积分。
- `frontend/src/lib/`：HTTP、草稿保存、日期、安卓消息通道、故障信息。不依赖具体页面 DOM。
- `frontend/src/features/speech/`：录音和识别生命周期，返回文字，不负责发布故事。设备离开页面时停止录音。
- `frontend/src/styles/`：原有低饱和配色、圆角卡片和移动端布局。保留产品风格，不引入另一套通用后台界面。
- `backend/domain/`：按记录、约定、故事、资料、愿望、分类、见面、导入分开处理业务规则。`commands.cjs` 仅分发操作，`points.cjs` 负责服务端积分。
- `backend/routes/`：认证、操作接口、兑换、历史及旧数据兼容接口。
- `backend/repository.cjs`：SQLite 实体读写、版本、快照和操作去重；`database.cjs`：数据库初始化；`errors.cjs`：错误码与脱敏日志。
- `backend/services/speech.cjs`：连接已配对笔记本 DSH，凭证只存服务器私有数据目录。
- `android/src/`：麦克风/提醒权限、通知、应用更新和系统文件保存。安卓能力必须检查可信网站来源。
- `ops/build.mjs`、`ops/package-release.mjs`：构建与制作发布包。
- `ops/updater-v2.cjs`：平板检查正式 Release、验证构建产物、备份、预运行、启用与代码回退。

禁止将用户数据库、草稿、备份、真实账号密码、DSH Cookie、SSH 私钥、APK 签名密钥和本机截图提交到 GitHub。

## 模块边界与依赖方向

### 产品和运行边界

这是两个人使用的生活记录应用：记录日常、约定与打卡、积分兑换、共同安排、故事接龙和回看。移动端优先，保留现有视觉风格和“今天、一起、兑换、回看”四个主导航，设置从页面右上角进入。新增功能优先放进对应业务模块，不能因为加功能就自动增设主导航、换 UI 框架或重做视觉风格。

当前是一个 Node.js 24 进程加 SQLite 的模块化单体，Vue 前端由同站点提供，安卓是 WebView 加少量原生能力。SQLite 是服务端的共享事实来源；浏览器 localStorage 只保存草稿、待提交操作及故障信息，不是第二份权威账本。平板承载网站运行，不在平板安装前端构建工具链。

扩展规则：维持单体部署，先按模块拆职责。没有相应需求和容量证据，不引入微服务、Redis、独立消息队列、多套前端状态库或多个同时写同一数据库的服务进程。外部识别服务是适配器，不得变成应用内部业务的依赖中心。

### 前端依赖

正常写入路径：页面/编辑器 → `stores/space.ts` → `lib/api.ts` → 后端。展示路径：服务器返回的可见快照 → store 的只读计算 → 页面。

- `main.ts` 只装配 Vue、Pinia、路由和样式。当前使用 hash 路由；`/#/points` 是兑换页，不能凭文件名改成 `/wallet`。
- `App.vue` 管理登录与应用外壳、导航、同步状态、待处理操作面板及短暂提示，不承接记录、目标、兑换等业务表单。成功提示自动消失且不拦截下方点击。
- `features/` 管理对应功能的展示、表单和用户交互。编辑中的值放局部状态或 `useDraft`，不得双向绑定后直接改 `s.data`，也不得用 DOM 查询或 HTML 字符串拼接接管其他页面。
- `stores/space.ts` 是当前的会话和同步协调入口：`init/login/logout/refresh`、`submit/flush/retry/resolve`、`redeem`、旧副本恢复。`member/balance/progress` 是读取服务器状态的展示计算，不代表客户端有发分权限。新增功能不得再创建第二份空间快照、另一套刷新计时器或私有的重试队列。
- `models.ts` 定义前端数据契约。改业务字段时必须同时核对后端字段校验、旧数据默认值和测试，不能只改 TypeScript 接口让类型检查通过。
- `lib/api.ts` 统一同源 HTTP、超时和 `ApiError`；`lib/task.ts` 统一按钮防重复及页面错误；`lib/draft.ts` 管理表单草稿；`lib/date.ts` 统一日期与周范围；`lib/diagnostics.ts` 只记脱敏故障码；`lib/native.ts` 是安卓消息通道的唯一前端适配入口。
- `components/` 仅放跨功能复用的展示和交互，如 `PageHead/Modal/Icon`。公共组件通过 props/emits 工作，不在组件内部兑换积分、修改账号或访问数据库。仅被一个功能使用的编辑器留在该功能目录，不为“通用”提前抽象。
- `styles/theme.css` 保留现有设计基础，`styles/app.css` 放 Vue 页面与公共布局补充。局部样式优先限定到组件或功能类名；改全局按钮、弹层、导航层级时，要检查所有页面和短屏手机。

当前有明确的非队列接口：登录/注册/邀请/改密/登出、历史读取、语音请求和兑换。部分页面经 `api/post` 调用这些专门接口，属于既有边界；新记录、约定、故事和配置写入不得借此绕过 `submit`。新增专门接口时应有明确的事务、重试和生命周期理由，并在本文登记。

### 后端依赖

正常命令路径：`server.cjs` → `backend/app.cjs` → `routes/commands.cjs` → `domain/commands.cjs` 分发 → 业务处理器 → 积分协调、整体校验 → `repository.cjs` 保存 → 返回按权限过滤的快照。

- `server.cjs` 是稳定启动入口：源码运行加载 `backend/app.cjs`，发布包加载 `runtime.cjs`。不得往启动器添加业务；`dist/runtime.cjs` 是构建产物，不能手改。
- `app.cjs` 管理 HTTP 装配、安全响应头、同源检查、静态文件、路由顺序和统一异常出口；`http.cjs` 管理读 JSON、写 JSON 和来源判断；`security.cjs` 管理口令散列和会话解析。业务模块不得自行实现第二套鉴权。
- `routes/commands.cjs` 管理命令收件、去重、事务及返回值。当前一次命令在 `BEGIN IMMEDIATE` 内完成读取、领域变更、`reconcilePoints`、`validState`、保存与收据写入；任何一步失败均回滚。事务内不得等待外部网络、录音识别或文件选择窗口。
- `domain/commands.cjs` 只登记处理器并提供 `find/version/create` 上下文；业务处理器命中自己的命令返回 `true`，不处理返回 `false`。不得把所有业务分支继续堆进分发器。
- `domain/` 处理业务字段、所有权、版本和状态转换，操作传入的数据副本。不得依赖 Vue、页面 DOM、HTTP req/res、SQLite 连接或外部服务。使用 `validation.cjs` 与 `errors.cjs` 的校验/领域错误帮助函数。
- `repository.cjs` 管理实体投影、逐项版本、兼容状态和历史快照。`database.cjs` 初始化连接与基础表，`backups.cjs` 管理一致备份。新业务不能各自建一份持久化文件或在页面请求里另开 SQLite 连接。
- 当前认证、兑换和历史兼容路由仍有专用 SQL 及事务逻辑，这是现有实现，不是“所有 SQL 都已移入 repository”。维护这些流程时保持原子性；新实体的常规 CRUD 应走命令与 repository，不能再复制一套快照保存逻辑。
- `services/speech.cjs` 只适配外部语音服务的能力查询、格式/大小校验、并发限制与请求。它不发布故事、不写积分。新增外部服务放 `services/`，由对应路由调用，凭证从服务端私有配置读取。

禁止反向依赖：领域模块调用路由、repository 调用页面、通用 HTTP 工具调用具体业务、安卓端直接修改账本。跨领域流程由上层明确协调，共用的小型规则提取到职责清楚的工具模块，不互相循环调用处理器。

## 身份、数据和版本的共同定义

- `Session.account` 是稳定登录账号；昵称、头像属于 `members`，不能拿昵称当用户主键。`Session.spaceId` 是空间隔离边界，后端从会话查出，不能相信客户端传来的空间 ID。
- `Session.slot` 是当前账号在这个双人空间内的 `me/him` 槽位，并非“任何登录者都叫 me”。v2 数据保留统一槽位，前端通过 `s.slot/s.other` 判断本人和对方。仅旧副本恢复函数允许转换旧视角数据；不能把整份 v2 数据对调 ID。
- 业务 `memberId` 由服务器设置或校验。客户端隐藏按钮只是交互，不是权限校验。空间内共享内容也不自动等于双方都能编辑，具体看所属业务的定义。
- 目标 `scope: "me" | "both"` 表示个人/共同，个人所有者由 `memberId` 决定；愿望的 `scope: "me" | "him" | "both"` 指实际空间槽位。两个字段同名但语义不同，不能写一个全局“scope 转换”混用。
- `visibility` 是记录/约定的可见范围，`wallet` 是积分钱包，不能用一个字段替代另一个。私密内容也可能产生个人积分；账户余额不等于记录的公开范围。
- 空间 `revision` 用于整体快照和旧版恢复；`versions[collection][id]` 用于单条编辑冲突，二者不能混用。`settings/couple` 也有独立版本。编辑器打开时保存版本；提交时不得偷偷读取最新版本覆盖它。
- 命令 `id` 是每次操作的唯一请求编号，`payload.id` 是实体编号。重发同一操作保留请求编号和原始内容；用户核对冲突后决定重新修改才创建新操作编号。不能每次网络重试重新发号。
- bootstrap 返回的是按当前账号过滤后的快照，不是完整数据库。不得把“前端没收到的行”当成“被删除的行”。所有新增写入都必须从服务器当前完整状态执行局部变更。
- 新创建的实体使用稳定唯一 ID，数组位置、日期和显示名称都不能充当 ID。修改原对象时保留未知的旧字段；删字段需显式迁移，不能靠重建对象悄悄丢掉。

当前几个版本号分别是：`package.json` 网页/服务端版本、`/health.protocol` 接口协议代际、`SpaceData.version` 数据结构代际（当前 4）、`schema_migrations` 的 SQLite 迁移序号、安卓 `versionCode/versionName`。它们用途不同，不能为了“统一版本”一起递增。加可选字段不自动意味着要改协议代际或重新打 APK。

## 业务模块定义

### 账号、邀请与个人资料

当前入口：`AuthPage.vue`、`SettingsPage.vue`、`routes/auth.cjs`、`security.cjs`、`domain/profiles.cjs`。认证与邀请使用专门接口，资料走 `profile.update`，共同起始日期走 `couple.update`。

账号与口令属于 `users/sessions`，空间归属属于 `spaces/space_members`，邀请属于 `invitations`，显示资料属于 `members`，共同起始日期属于 `couple`。当前一个账号只属于一个两人空间；邀请用于第二位注册加入，空间满员后不能继续邀请。改密码会撤销该账号既有会话。只能修改本人资料，共同设置按版本检查。

扩展规则：增加资料字段放资料模块；增加登录方式放认证模块，并明确如何绑定稳定账号。换伴侣、退出空间、多空间、三人以上协作都是身份模型变更，不能仅放宽成员数量、修改槽位字符串或删除唯一约束。必须先定义旧数据归属、历史可见范围、邀请失效与会话行为，再设计迁移和测试。

### 日常记录与回看

当前入口：`TodayPage.vue`、`features/records/RecordEditor.vue`、`ReviewPage.vue`、`domain/records.cjs`。写入命令是 `record.create/update/delete`，集合为 `entries`。

一条记录包含所属槽位、日期、开始/结束、时长、内容、备注、分类、可见范围、心情及可选 `goalId`。服务器计算时长并验证字段，只允许本人修改/删除。回看是记录的月份、日期、分类和心情投影，没有另一份“回看记录表”，不写回统计结果。

扩展规则：增加筛选、统计或日历展示，优先用现有可见记录做只读计算；确需服务端查询时仍先应用空间及可见范围。增加记录字段要明确默认值、表单草稿、编辑/删除、导入导出和旧数据兼容，不能为一张统计图另造一份记录来源。

### 约定、长期目标与打卡

当前入口：`GoalsPage.vue`、`features/goals/GoalEditor.vue`、`domain/goals.cjs`。命令是 `goal.create/update/join/archive`，集合为 `goals`；打卡仍创建 `entries`，靠明确的 `entry.goalId` 关联，不存在独立的打卡写入接口。

`kind` 区分每周重复与一次性约定；`status` 为 `active/done/dropped`。共同约定由另一位 `join` 后生效，所有者负责修改内容/分值和归档。进度按打卡人分别计算，每周约定以周一到当天为范围，一次性约定看累计关联记录。一次性约定不能反复打卡，但记一次打卡也不会自动归档约定，结束需明确归档操作。

当前个人进行中约定最多三个；重复约定单次积分 1–5，一次性 1–30，每周次数 1–21。`keywords` 仍是兼容字段，新建时为空数组，当前不会靠文字/关键词自动命中目标。“每周运动”和“跑步记录”的关系由记录时选择约定来建立。

扩展规则：增加目标频率、暂停、提醒或打卡方式，要同时核对 `GoalEditor`、`goalFields`、记录关联验证、`progress`、积分核算及通知筛选。不能在目标页面直接增加进度数或积分，也不能用标题相似来自动补关联。改变目标归属或积分规则属于产品行为变化，需有明确需求与旧打卡处理说明，不能由 AI 擅自重算历史分值。

### 积分、愿望、奖励与兑换

当前入口：`WalletPage.vue`、`features/wallet/WishEditor.vue`、`domain/wishes.cjs`、`domain/points.cjs`、`routes/redemptions.cjs`。配置命令是 `wish.save/complete`、`reward.save`；实际兑换走 `/api/redeem`，取消待确认申请走 `/api/redeem/cancel`。

`wishlist/rewards` 是空间内的愿望/奖励配置；`points_ledger` 是服务端积分流水；`redemptions` 是兑换及双方确认状态。当前奖励清单配置不是私密实体，个人钱包也不表示奖励配置仅本人可见/可编辑。若要支持私密奖励，必须另外定义所有者与过滤规则，不能仅增加一个前端标签。

个人目标打卡分进入打卡人的 `mine`，共同目标打卡分进入打卡人的 `ours`。余额是服务端流水减已生效支出，不是页面可编辑数字。共同愿望总价为偶数，双方各支付一半共同分；申请阶段为 `pending`，对方确认时再次核对双方余额和愿望配置才完成扣分。个人愿望由对应本人兑换；小奖励扣兑换者的个人分。定价“待定”的愿望不能当成免费商品兑换。

当前积分还含日期边界与周保底，准确规则以 `points.cjs` 和 `test/wallet.cjs` 为准：关联目标的记录是主要打卡来源；无目标记录存在 2026-11-02 当日的兼容发分窗口，不能概括成“任何日期记一笔都发分”或“历史普通记录完全不发分”。修改、删除打卡可能影响积分；若已消费的分将被撤回导致不足，服务器拒绝该变更。目标调价不能顺手重写已确认的旧打卡奖励。

扩展规则：新增赚分来源要定义来源 ID、防重复、钱包、撤回条件和历史生效日期，在服务端核算。新增消费方式复用服务端事务、幂等编号和余额检查，不能只把按钮设为 disabled，更不能由前端上传积分流水。兑换重试编号与普通命令队列是不同机制，不能未经设计就合并或删除本机兑换编号。

### 共同安排、见面与分类

当前入口：`TogetherPage.vue`、`SettingsPage.vue`、`domain/meetings.cjs`、`domain/categories.cjs`。`milestones` 中 `kind: "meet"` 承载见面日期与安排，命令是 `meeting.save`；共同愿望仍使用 `wishlist`，不能在“一起”和“兑换”各保存一份。创意是“一起”里的子栏目，故事编辑是独立路由。

分类存放在 `categories`，通过 `category.save/move` 修改名称、说明、颜色和顺序。`none` 是保留的“未分类”，不能编辑或移动；记录以分类 ID 引用，不按名称关联。分类、共同起始日期和见面安排是空间配置，双方按相应版本编辑。

扩展规则：其他共同活动若只是见面安排的展示，可复用当前数据；若生命周期、参与规则不同，建立有清晰类型的新业务实体，不要把所有对象都塞进 `milestones` 或设置页。增加分类删除功能时须先定义已有记录归类、目标引用与并发行为，不能只删除列表项。

### 故事与语音输入

当前入口：`StoryPage.vue`、`features/speech/useSpeech.ts`、`domain/stories.cjs`、`services/speech.cjs`。`story.publish` 只发布一段，集合为 `story_entries`。服务器指定作者、当天日期和递增 `seq`，同草稿 ID/同正文重复提交不会重复发布。界面有续写提示，但当前服务端没有“必须严格一人一段轮流”的限制；不得把提示语当成已实现的权限规则。

故事草稿属于当前账号；语音只返回文字给草稿，识别完成不自动发布。单段上限 10000，当前按 JavaScript 字符串长度计数，并非语言学字数；超过剩余容量的识别结果单独保留，不静默截掉已有文字。离开页面会停止录音并释放麦克风。

录音上限必须取接口能力与 180 秒的较小值，并同时考虑 16kHz、单声道、16 位 PCM WAV 的字节限制；Base64 与 HTTP 请求体还会增加体积。不能只调大前端计时器。当前 `/api/speech/config` 查询能力，`/api/speech/transcribe` 接收音频，外部凭证只在服务端。

扩展规则：把语音用于其他输入框，复用录音 composable，新增页面只决定如何接收文字。增加创意游戏、故事评论/编辑或严格轮流规则时新定义命令、所有权、版本、排序和冲突规则；不能让语音模块操作故事列表，也不能让客户端指定最终序号或伪造作者。

### 草稿、同步、冲突、历史和备份

当前草稿由 `useDraft` 管理，常规提交由 `space.submit` 先持久化账号/空间关联的操作，再尝试发送。`submit` 返回不一定代表已写入服务器，也可能已排队；页面文案必须区分“已保存”和“已保存在本机，等待提交”。清理表单草稿前，必须保证操作正文已由队列可靠接管，不能清空后才保存队列。

网络失败保留 waiting；明确的 409 留作 conflict，其他可处理错误留作 error；本机副本成功提交或用户明确放弃后才移除。后台约 15 秒尝试刷新/发送，不是 WebSocket、CRDT 或逐字实时协作。新增共享编辑不能依赖“谁最后上传整份数据谁赢”。

`domain/state.cjs` 的 `visibleState` 过滤对方私密记录/目标，`visibleHistory` 对历史进一步限制，避免以前公开、后来私密的内容从旧快照泄露。新增私密实体必须登记当前快照、历史、相关派生标题、导出和导入的可见范围；只过滤页面不够。

新备份恢复只补回当前账号缺失的个人内容，不覆盖相同 ID 的现有内容、不导入积分流水；旧副本恢复走专门兼容路径。备份是恢复材料，不能当成一次“正常保存”整份覆盖空间。增加新可恢复实体时要在导出格式与恢复白名单中明确登记，不自动接受备份里的所有键。

### 安卓、通知与文件导出

原生文件在 `android/src/cn/yidiangames/women/`：`MainActivity.java` 管理可信站点 WebView、权限和消息通道；`ReminderStore.java` 保存本机提醒并调度，`ReminderReceiver.java` 发通知，`ReminderRestoreReceiver.java` 恢复系统事件后的调度；`DocumentExports.java` 负责系统文件保存；`AppUpdates.java` 负责版本检查、下载和交给安卓安装。

`lib/native.ts` 与这些类约定消息类型、稳定账号、请求编号及返回结果。当前有提醒 `sync/clear/request-permission` 与分块导出 `export-start/chunk/end`。导出只有实际写文件成功才确认；WebView 不能把普通下载链接被点击当作本机文件已保存。

当前通知是本机目标定时提醒，不是服务端推送、双方聊天或远程消息投递系统。增加通知类型要定义唯一 ID、账号归属、去重、取消、改时间、登出/换账号和设备重启后的行为；手机浏览器并不自动拥有安卓消息通道。

扩展规则：原生权限或消息协议改变，须保持可信域名/来源限制、兼容已安装的旧 APK，按版本逐步启用。没有新能力的旧 App 要有明确退路，不能因网页先上线而无限等待原生回执。原生变更需同签名 APK 和实体设备验证，不能以浏览器模拟通过代替。

### 诊断、构建与运行支撑

`errors.cjs` 统一领域错误和服务端滚动错误日志，`lib/diagnostics.ts` 保存前端最近的脱敏事件，设置页提供导出入口。新增失败路径应有可定位的路由/功能、错误码和请求编号，不记录密码、Cookie、录音、表单正文或整份 bootstrap。不要把所有异常吞掉只显示成功，也不要直接把底层堆栈弹给用户；用户内容在失败时仍应保留。

`backend/cli.cjs` 承载已有的初始化、口令管理和备份命令，不是新的注册入口。`ops/migrate-legacy-accounts.cjs` 是旧账号迁移工具，不参与日常登录，更不能被普通启动或 CI 自动执行。普通用户与测试账号通过注册/邀请创建，不重新引入“第一位/第二位”登录方式。

`ops/build.mjs` 做类型检查、Vite 前端构建和后端/更新器打包，`ops/package-release.mjs` 生成带提交号的清单与压缩包校验，`.github/workflows/release.yml` 负责 GitHub 测试和发布附件。`ops/verify-migration.cjs` 只验证备份副本；`ops/updater-v2.cjs` 在平板验证并部署；`ops/termux-release-boot.sh` 是启动配套脚本。这些是构建/运维模块，不承接页面业务。

新增图片等固定素材按 `vite.config.ts` 的配置放到 `frontend/static/`（需要时建立目录），或由 Vue 源码导入。根目录 `public/app-version.json` 是由构建流程单独复制的安卓版本元数据，不能假定把任意网页脚本塞进根 `public/` 就会被发布。普通功能开发不手改 `dist/`、Release 压缩包、线上静态资源或更新器；运维变更必须另外说明影响和回退。

## 后续扩展流程

### 开始修改前

1. 读本文和 `AGENTS.md`，检查 `git status`、当前分支及与 `origin/main` 的差异。先理解现有未提交修改，不执行 `reset --hard`、`git clean` 或删除不认识的文件来获得“干净环境”。
2. 写清这次用户操作、预期结果、所属模块、个人/共同范围、是否改数据或安卓。只改达到需求所需的文件；不以实现小功能为由顺手更换框架、放宽积分、扩大公开范围或重构全项目。
3. 定位现有组件、命令、校验和相应测试，列出会受影响的读取/写入路径。若是未定义的产品行为，先提出具体方案；已有授权足够的实现细节自行完成，不重复申请权限。

给接手 AI 的任务说明至少写清以下内容；这是确定实现范围，不是要求用户再审批一次已有授权：

```text
用户操作与预期结果：
所属业务模块与准备修改的文件：
数据字段、所有者、可见范围及关联对象：
使用的命令/接口与冲突、重试方式：
是否涉及积分、历史、备份、迁移或安卓能力：
需要保留的旧行为与明确不改的范围：
本机测试、页面验收及实际成功判据：
```

### 给现有实体加字段

例如给约定增加一项新的说明字段：先定义类型、可选性、长度、默认值及谁可编辑，然后依次检查 `models.ts`、表单草稿初值、提交 payload、后端字段白名单/校验和领域处理器、`validState`、列表/详情展示、导入导出与测试。这个例子是扩展步骤，不代表当前已有该说明字段。

读旧数据时提供兼容默认值，不为一个可选展示字段重建整张表或全量替换实体。编辑函数保留未修改字段；若影响积分、提醒或隐私，同时更新对应模块。加字段后验证旧记录仍能打开并修改，旧备份仍能被正确拒绝或兼容。

### 增加新的独立业务实体

例如未来增加故事评论，按以下顺序完成；当前没有这个功能：

1. 定义稳定 ID、关联故事 ID、作者来源、内容校验、可见范围、创建/修改/删除规则和是否影响积分。关联对象必须属于同一空间，不能只凭传来的 ID 找到就允许写。
2. 在 `models.ts` 定义类型和 `SpaceData` 字段；同步补齐 `domain/seed.cjs` 和 store 空状态的默认集合。
3. 在 `repository.cjs` 的集合/投影规则与 `domain/state.cjs` 的结构校验、当前/历史可见规则中登记。新集合在旧空间没有值时要有明确初始化方案；只给新注册空间加 seed 不会更新老空间。
4. 新建 `domain/` 处理器并登记到 `domain/commands.cjs`。创建由服务器确定所有者；编辑/删除先查对象、校验权限，再检查打开表单时的实体版本；不要靠 `create` 帮助函数代替完整的字段/权限校验。
5. 在相应 `features/` 下加组件或编辑器，经 `s.submit` 调用。只有确需独立页面时才在 `main.ts` 登记路由，沿用既有导航与基础组件。
6. 明确该实体是否进入历史和备份恢复；若不支持恢复，文档中明确，而非默认接收任意备份字段。补正常流程、越权、并发、重复提交和旧数据兼容测试，再更新本文的模块与命令说明。

若需要新 SQLite 表，用独立迁移序号、事务、幂等执行和备份副本验证。不能在路由中遇到旧数据就随手建表，也不能把 schema_migrations 序号与用户业务版本混为一谈。

特别注意：当前 repository 会按 `entity_meta` 中的集合顺序恢复数据。给 `collections` 加名字时，必须同步处理旧 meta 没有该集合顺序的情况，不能只追加数组名后直接对缺失的 `orders[新集合]` 调用 `map`。用包含旧 meta 的副本验证，不能只测试一份空数据库。

### 增加命令或专门接口

普通实体变更优先使用既有命令管道，不为每个按钮再设计一个 HTTP 保存接口。命令使用 `业务.动作` 名称，准确描述单次变更；批量操作必须说明逐项失败还是整笔回滚，不允许把全量空间对象塞进一个“通用更新”命令。

现有领域处理器接口为 `handler(ctx)`，上下文包含 `data/p/type/slot/session/find/version/create`。`p` 是 payload，`find(collection)` 使用 `p.id`；`version(collection, item)` 抛出带当前实体和版本的 409；`create(collection, item)` 检查 ID 冲突后加入集合。新命令应使用 `fail` 给出错误码、状态及可理解提示，未知命令继续由分发器拒绝。

命令成功返回现有 bootstrap 结构，不自行回另一套 `data` 或遗漏 session/versions。逐项版本冲突的 409 `details` 要包含冲突集合、实体、当前值和版本，且只能在验证调用者有权访问该对象后返回，不能为了展示冲突泄露私密内容。ID 重复、申请状态变化等其他 409 不一定有这些字段，前端不能一律提供“强制覆盖”来解决。401 交给登录流程，网络失败保留本机操作；重试不能把一个确定的校验错误当成断网无限重发。

新增专门接口时，在 `app.cjs` 挂接并说明鉴权、同源检查、请求大小、超时、事务边界、重试和响应类型；外部请求在事务外完成。默认请求体上限是 `http.cjs` 的 2 MiB，语音路由另设 8 MiB；还要核对反向代理限制，不能全站无限放大。不要为了解决一个接口错误关闭同源、CSP 或可信来源限制。

替换外部语音提供方时，优先保持服务适配器的 `config()` / `transcribe(audio)` 及对前端的 `maxSeconds/maxBytes`、`text` 契约；提供方鉴权和响应格式转换留在 `services/`。若契约确需变化，更新调用方、兼容策略和测试，不能把提供方差异分别写进多个输入页面。其他外部能力也采用相同的适配边界，不为未来可能的扩展提前建立空框架。

### 修改共享规则、积分或迁移

先列出受影响的旧数据和不变条件。至少覆盖本人、对方、另一个空间、未登录四种身份，以及重复请求、双方同时改不同对象、双方同时改同一对象。预期是不同对象互不覆盖，同一对象按明确冲突/状态规则处理；不能简单把所有并发都吞掉。

数据迁移必须在独立副本上执行与重复执行，比较账号凭证、空间归属、记录顺序、无 ID 旧条目、余额和历史。现有 `entity_meta` 不只是杂项配置，还保存集合顺序和无法按普通 ID 索引的兼容条目；不能删除它们来“精简 JSON”。`state/space_state` 与实体投影当前仍共同服务兼容读取，不能只写其中一个就宣称迁移完成。

新增字段/表尽量向后兼容。删除旧接口、旧 JSON、历史字段或旧恢复逻辑前，需要确认仍受支持的客户端和副本都已完成过渡，并提供迁移、验证和代码回退方案；没有这些证据不能删除。代码回退与数据库回退分别处理，不得为了恢复旧代码自动覆盖发布期间的新数据。

本维护电脑的现有配置位于 `$env:USERPROFILE\.codex\private-backups\women-ledger\qa-browser-accounts.json`。后续维护 AI 先检查该文件并复用已有账号，不要每次向用户申请新账号；其他电脑通过私下渠道建立相同结构的本机私有配置。

PowerShell（Node.js 24，先执行 `npm ci` 和 `npx playwright install chromium`）：

```powershell
$env:WOMEN_TEST_ACCOUNTS_FILE = 'C:\私有目录\qa-browser-accounts.json'
$env:WOMEN_TEST_OUTPUT_DIR = 'C:\私有目录\women-browser-reports'
# 可选：$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
# 可选：$env:WOMEN_TEST_HEADED = '1' # 显示浏览器，便于人工观察
npm run test:live-ui
```

每次运行创建带唯一 `QA-时间-随机值` 前缀的记录、约定和奖励，保留这些测试空间数据供核查，不批量清空账号或其他记录。截图和 `report.json` 保存在指定私有输出目录的运行子目录；报告区分通过步骤和失败步骤，退出码非零表示失败。失败时先看截图和脱敏报告，不为了通过测试去修改真实空间、关闭权限检查或忽略错误。测试账号长期累积积分到 10000 时应人工审核测试空间，不能扩大兑换上限来迁就测试。

现有脚本每次会创建一个个人约定，仍受“最多三个进行中个人约定”的真实规则限制。达到上限时，先核对测试空间和 `QA-` 标记，通过该测试账号页面明确归档之前的测试约定，再重新验收；不得提高全站上限、清空数据库或另建一批账号绕开规则。普通 CI 使用临时数据库；线上验收虽然连接同一服务，也只允许操作已核对的专用测试空间，不因此获得全库或真实成员数据的修改权限。

委派给子代理或 DeepSeek 时，给它最新代码和本文，说明仅限专用测试空间；让它返回运行报告路径、通过/失败步骤、复现操作及截图。测试应读取最新页面控件并验证实际保存结果，不把“按钮点过了”当作功能通过，不让代理把账号文件、报告或截图提交到仓库。

## 数据与接口规则

新前端通过 `GET /api/v2/bootstrap` 获取当前账号的可见数据、逐项版本和稳定账号信息。数据库中的 `me/him` 是旧双人空间的内部槽位，当前身份由服务器会话绑定，前端不再整份互换成员 ID。

写入使用 `POST /api/v2/commands`：

```json
{
  "id": "每次操作唯一的 UUID",
  "type": "record.update",
  "expectedVersion": 3,
  "payload": {
    "id": "记录 ID",
    "content": "修改后的文字",
    "date": "2026-11-02",
    "start": "10:00",
    "end": "11:00",
    "visibility": "shared"
  }
}
```

- 新增、修改、加入、发布是不同命令；页面不上传整份账本。
- 编辑时记录打开表单当时的版本，不要在提交时偷偷换成最新版本；不匹配返回 409 和该条内容当前版本。
- 相同操作编号、相同内容重复提交只执行一次；同编号不同内容会拒绝。
- 服务器检查所属空间、记录所有者、字段长度、约定状态和积分；前端校验只帮助交互。
- 故事发布限制 10000 字，服务器分配接龙顺序。个人记录默认可选双方可见或私密。
- 兑换沿用专门的 `/api/redeem` 与 `/api/redeem/cancel` 事务接口，积分不能由前端设置。
- 添加新功能：新建功能组件、领域处理器和相应测试，注册处理器；不要往一个全局点击事件里不断追加分支。

## 本机草稿与恢复

待提交操作使用 `women.v2.pending.<稳定账号>`，并校验所属空间；故事和表单草稿使用账号及功能分开的键。App 重启不会依赖旧页面会话编号来寻找待提交操作。

暂时断网会保留队列并重试。真实冲突只暂停对应操作，保留本机内容，让用户核对当前服务器内容后选择。明确放弃操作才删除本机副本；不能把“点过下载”当作“已经保存文件”。

旧版 `women.pending.v1.*` 副本仍会查找，并提供尝试恢复。恢复通过旧版兼容接口的版本合并完成，成功前不删除原副本；发生冲突时继续保留。新版备份导入只补充当前账号缺失的个人内容，不整体替换双人空间、不导入积分流水。

安卓 0.4.0 使用系统文件选择器保存导出文件，只有实际写入成功才回报成功；取消或失败保留原始内容。

## SQLite 兼容迁移

迁移是新增表，不删除原账号、空间、状态或历史表。新增 `entity_rows`、`entity_meta`、`command_receipts` 和 `schema_migrations`，支持逐项版本与操作去重。

实体表服务新接口；兼容状态与历史快照保留用于旧客户端恢复、历史核对及回退。旧兼容接口写入后，新接口按版本刷新实体投影。迁移保存原数组顺序、无 ID 的旧记录、积分与历史字段，重复启动不会重复迁移。这个兼容边界是数据迁移用途，不是继续运行旧版前端。

每次发布前必须用 SQLite 在线备份创建一致副本，检查完整性，并让新版在独立副本上启动。不得把生产数据库文件当作本机/CI 测试库，也不得在全库运行会改写真实成员数据的测试；已授权的线上页面验收仅按前述专用账号和空间约束执行。不得只复制正在写入的主数据库或删除 WAL。

维护者可用下列命令对一个已经完成的在线备份做独立副本核对。工具不会修改传入备份，也不打印账本正文或凭证；它比较原始数据、账号凭证和实体投影，然后删除自己创建的临时目录：

```sh
node ops/verify-migration.cjs /私有目录/在线备份.sqlite dist/server.cjs
```

## GitHub 构建与网页发布

1. 本机完成测试，将代码合并到最新 `main`。普通推送只触发 CI，不更新线上网站。
2. 在 GitHub 创建指向准备上线提交的正式 Release，例如 `v2.0.0`；不要勾选预发布。
3. `.github/workflows/release.yml` 在 GitHub 的 Linux 运行器安装依赖、构建 Vue、打包 Node 后端并运行测试。通过后附加 `women-web-v2.tar.gz` 与 `.sha256` 到 Release。
4. 平板约每五分钟检查。构建产物尚未出现时继续等待，不从源代码临时构建。
5. 平板核对校验和、标签提交属于 `main`、压缩包路径及运行文件；备份数据、用副本试运行，启用新版并检查健康状态。

GitHub 构建的是网页和独立 Node 运行文件；平板不需要 `npm ci`、Vue 构建工具或 `node_modules`。

`dist/` 是生成目录，不提交。发布包只包含启动器、`runtime.cjs`、前端构建文件和发布清单。源代码中的 `server.cjs` 优先加载 `backend/`；发布目录没有该源码目录，加载独立 `runtime.cjs`。

网页发布不代表 APK 已更新。前端热更新不能新增安卓权限。静态资源使用带内容哈希的文件名；HTML 不缓存。部署会先放置新资源、重启并验证后端，再切换 HTML，保留原资源供已打开的页面使用。

## 安卓打包与自动更新

沿用仓库 `android/build.ps1`，需要 JDK、Android SDK Platform 33、Build-Tools 33.0.2。执行时可显式传 `-JavaHome`、`-SdkRoot`。

修改安卓时递增 `AndroidManifest.xml` 的 `versionCode` 和 `versionName`，构建脚本会生成对应 `public/app-version.json`。必须使用原签名；不同签名不能覆盖安装。签名文件留在维护者本机，不上传仓库，不交给 GitHub 普通构建任务。

将构建出的 APK 以 `women-ledger-版本.apk` 命名，作为资产附加到同一个 GitHub Release。平板检查器发现新安卓版本而缺少 APK 时等待，不提前部署一个要求用户下载不存在安装包的版本。原有 APK 已在平板下载目录时可以复用。

App 0.3.2 及以上会在启动时检查版本、提示更新、下载并交给安卓安装界面。安卓仍要求用户确认；首次可能需要允许本 App 安装未知应用。更新后保留应用数据。网络不可用时不会把现有 App 锁死。文件保存能力需要 0.4.0。

## 运行、日志与回退

平板运行目录 `~/women-ledger`，数据在 `data/ledger.sqlite`；DSH 凭证在私有 `data/dsh-speech-cookie.txt`。云服务器为 HTTPS 与平板反向隧道入口，保留现有服务配置。

服务端错误日志：`data/logs/errors.jsonl`，自动限制文件大小，只记录时间、请求编号、路由、错误码和错误类型，不记录账本文字、密码、Cookie 或录音。前端设置页可导出最近的脱敏故障信息。

部署检查器日志：`release-updater.log`，已部署状态：`release-updater-state.json`，发布前备份：`data/backups/`，旧代码：`release-updater-work/`。这些仍在平板本机，不等于异地备份。

启用失败时尝试回退旧代码，不自动恢复旧数据库，以免覆盖发布期间已经写入的内容。失败提交暂停重复部署，人工检查后再发布修复提交。数据库回退必须停服、另外保留当前完整数据，再用副本验证恢复；不可直接覆盖。

首次从 v1 迁移需要维护者安装新版发布检查器 `dist/release-updater.cjs`，保留原有 SSH 和私有配置。以后网站发布按 Release 构建产物执行。部署检查器本身的升级仍应由维护者单独验证，不在普通页面发布中自动执行新的运维程序。
