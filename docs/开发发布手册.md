# 「我们」v2 开发、构建与发布手册

给维护者和协作 AI：开始修改前先读取 `AGENTS.md` 和本文，执行 `git fetch origin main`，确认基于最新代码。不要直接修改服务器文件来代替提交和发布。

## 技术与目录

- `frontend/src/features/`：真实 Vue 3 单文件组件。按记录、约定、愿望积分、故事、回看、设置划分。各功能的编辑器在相应子目录中。
- `frontend/src/components/`：公共页面标题、弹层、图标。图标 SVG 来自既有设计，所有用户文本通过 Vue 插值转义。
- `frontend/src/stores/space.ts`：Pinia 管理空间快照、操作队列及会话协调。页面不要直接调用 `fetch` 或写服务器积分。
- `frontend/src/lib/`：HTTP、草稿保存、日期、安卓消息通道、故障信息。不依赖具体页面 DOM。
- `frontend/src/features/speech/`：录音和识别生命周期，返回文字，不负责发布故事。设备离开页面时停止录音。
- `frontend/src/styles/`：原有低饱和配色、圆角卡片和移动端布局。保留产品风格，不引入另一套通用后台界面。
- `backend/domain/`：按记录、约定、故事、资料、愿望、分类、见面、导入分开处理业务规则。`commands.cjs` 仅分发操作，`points.cjs` 负责服务端积分。
- `backend/routes/`：认证、操作接口、兑换、历史及旧数据兼容接口。
- `backend/repository.cjs`：SQLite 实体读写、版本、快照和操作去重；`database.cjs`：数据库初始化；`errors.cjs`：错误码与脱敏日志。
- `backend/services/speech.cjs`：连接已配对笔记本 DSH，凭证只存服务器私有数据目录。
- `android/src/`：麦克风/提醒权限、通知、应用更新和系统文件保存。安卓能力必须检查可信网站来源。
- `ops/build.mjs`、`ops/package-release.mjs`：构建与制作发布包。
- `ops/updater-v2.cjs`：平板检查正式 Release、验证构建产物、备份、预运行、启用与代码回退。

禁止将用户数据库、草稿、备份、真实账号密码、DSH Cookie、SSH 私钥、APK 签名密钥和本机截图提交到 GitHub。

## 本机运行

要求 Node.js 24，推荐使用锁定依赖：

```sh
npm ci
npx playwright install chromium
npm run build
node server.cjs
```

打开 `http://127.0.0.1:18763`。默认数据目录是本机项目的 `data/`，与平板独立。仅使用测试账号。

开发热更新时，在一个终端执行 `node server.cjs`，另一个执行 `npm run dev`，使用 Vite 显示的本机地址。`/api` 会代理到本机后端。不要让本机开发请求连接真实线上账本。

```sh
npm run typecheck
npm test
npm run pack
```

`npm test` 会先构建，再测试账号、权限、积分、历史兼容、逐项操作、并发、迁移、Vue 手机视口交互、语音、离线重启和发布产物。Playwright 可通过 `CHROME_PATH` 使用已有 Chrome；CI 自动安装 Chromium。

## 部署后的真实页面验收

本机自动测试通过后，还要验证实际部署域名的页面。复用两个以 `qa_women_` 开头的普通测试账号，由第一个账号邀请第二个，组成独立双人空间。两个测试账号不加入使用者的真实空间，也没有管理员权限。不需要每次注册新账号。

`test/live-ui.cjs` 使用两个独立 Chromium 浏览器会话，在 390×844 手机视口操作真实页面：通过登录表单登录，新增私密/共享记录并从对方页面核对可见范围；建立约定和打卡，核对进度与服务端发分；设置高于余额的奖励，确认兑换按钮禁用；同时提交双方记录，刷新后检查均保留。所有写入经过页面表单；只读 bootstrap 接口补充验证身份、数据和积分。浏览器移动视口证据不能代替实体 Android 的权限、录音、通知和安装测试。

该脚本是明确指定的部署后验收，不在 `npm test`、普通 CI 或每次启动时执行。维护者首次通过页面注册、邀请并核对专用空间后，在仓库外私有位置保存 JSON：

```json
{
  "baseUrl": "https://部署域名.example",
  "spaceId": "核对后的独立测试空间 UUID",
  "accounts": [
    { "username": "qa_women_a_example", "password": "在私有文件填写强密码" },
    { "username": "qa_women_b_example", "password": "在私有文件填写另一强密码" }
  ]
}
```

实际口令、会话、测试空间 ID 和账号配置不提交到 GitHub，不发给公开 Issue 或无关代理；需要其他维护者运行时通过私下渠道提供其本机配置。脚本要求明确的配置路径和输出路径，拒绝仓库内配置/截图路径、非 `qa_women_` 账号、`legacy` 空间以及不匹配的账号或成员。未通过身份核对之前不写入测试内容。

本维护电脑的现有配置位于 `$env:USERPROFILE\.codex\private-backups\women-ledger\qa-browser-accounts.json`。后续维护 AI 先检查该文件并复用已有账号，不要每次向用户申请新账号；其他电脑通过私下渠道建立相同结构的本机私有配置。

PowerShell（Node.js 24，先执行 `npm ci` 和 `npx playwright install chromium`）：

```powershell
$env:WOMEN_TEST_ACCOUNTS_FILE = 'C:\私有目录\qa-browser-accounts.json'
$env:WOMEN_TEST_OUTPUT_DIR = 'C:\私有目录\women-browser-reports'
# 可选：$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
# 可选：$env:WOMEN_TEST_HEADED = '1' # 显示浏览器，便于人工观察
npm run test:live-ui
```

每次运行创建带唯一 `QA-时间-随机值` 前缀的记录、约定和奖励，保留这些测试空间数据供核查，不批量清空账号或其他记录。截图和 `report.json` 保存在指定私有输出目录的运行子目录；报告区分通过步骤和失败步骤，退出码非零表示失败。失败时先看截图和脱敏报告，不为了通过测试去修改真实空间、关闭权限检查或忽略错误。测试账号长期累积积分到 10000 时应人工审核测试空间，不能扩大兑换上限来迁就测试。

委派给子代理或 DeepSeek 时，给它最新代码和本文，说明仅限专用测试空间；让它返回运行报告路径、通过/失败步骤、复现操作及截图。测试应读取最新页面控件并验证实际保存结果，不把“按钮点过了”当作功能通过，不让代理把账号文件、报告或截图提交到仓库。

## 数据与接口规则

新前端通过 `GET /api/v2/bootstrap` 获取当前账号的可见数据、逐项版本和稳定账号信息。数据库中的 `me/him` 是旧双人空间的内部槽位，当前身份由服务器会话绑定，前端不再整份互换成员 ID。

写入使用 `POST /api/v2/commands`：

```json
{
  "id": "每次操作唯一的 UUID",
  "type": "record.update",
  "expectedVersion": 3,
  "payload": {
    "id": "记录 ID",
    "content": "修改后的文字",
    "date": "2026-11-02",
    "start": "10:00",
    "end": "11:00",
    "visibility": "shared"
  }
}
```

- 新增、修改、加入、发布是不同命令；页面不上传整份账本。
- 编辑时记录打开表单当时的版本，不要在提交时偷偷换成最新版本；不匹配返回 409 和该条内容当前版本。
- 相同操作编号、相同内容重复提交只执行一次；同编号不同内容会拒绝。
- 服务器检查所属空间、记录所有者、字段长度、约定状态和积分；前端校验只帮助交互。
- 故事发布限制 10000 字，服务器分配接龙顺序。个人记录默认可选双方可见或私密。
- 兑换沿用专门的 `/api/redeem` 与 `/api/redeem/cancel` 事务接口，积分不能由前端设置。
- 添加新功能：新建功能组件、领域处理器和相应测试，注册处理器；不要往一个全局点击事件里不断追加分支。

## 本机草稿与恢复

待提交操作使用 `women.v2.pending.<稳定账号>`，并校验所属空间；故事和表单草稿使用账号及功能分开的键。App 重启不会依赖旧页面会话编号来寻找待提交操作。

暂时断网会保留队列并重试。真实冲突只暂停对应操作，保留本机内容，让用户核对当前服务器内容后选择。明确放弃操作才删除本机副本；不能把“点过下载”当作“已经保存文件”。

旧版 `women.pending.v1.*` 副本仍会查找，并提供尝试恢复。恢复通过旧版兼容接口的版本合并完成，成功前不删除原副本；发生冲突时继续保留。新版备份导入只补充当前账号缺失的个人内容，不整体替换双人空间、不导入积分流水。

安卓 0.4.0 使用系统文件选择器保存导出文件，只有实际写入成功才回报成功；取消或失败保留原始内容。

## SQLite 兼容迁移

迁移是新增表，不删除原账号、空间、状态或历史表。新增 `entity_rows`、`entity_meta`、`command_receipts` 和 `schema_migrations`，支持逐项版本与操作去重。

实体表服务新接口；兼容状态与历史快照保留用于旧客户端恢复、历史核对及回退。旧兼容接口写入后，新接口按版本刷新实体投影。迁移保存原数组顺序、无 ID 的旧记录、积分与历史字段，重复启动不会重复迁移。这个兼容边界是数据迁移用途，不是继续运行旧版前端。

每次发布前必须用 SQLite 在线备份创建一致副本，检查完整性，并让新版在独立副本上启动。不得用生产数据库跑自动测试。不得只复制正在写入的主数据库或删除 WAL。

维护者可用下列命令对一个已经完成的在线备份做独立副本核对。工具不会修改传入备份，也不打印账本正文或凭证；它比较原始数据、账号凭证和实体投影，然后删除自己创建的临时目录：

```sh
node ops/verify-migration.cjs /私有目录/在线备份.sqlite dist/server.cjs
```

## GitHub 构建与网页发布

1. 本机完成测试，将代码合并到最新 `main`。普通推送只触发 CI，不更新线上网站。
2. 在 GitHub 创建指向准备上线提交的正式 Release，例如 `v2.0.0`；不要勾选预发布。
3. `.github/workflows/release.yml` 在 GitHub 的 Linux 运行器安装依赖、构建 Vue、打包 Node 后端并运行测试。通过后附加 `women-web-v2.tar.gz` 与 `.sha256` 到 Release。
4. 平板约每五分钟检查。构建产物尚未出现时继续等待，不从源代码临时构建。
5. 平板核对校验和、标签提交属于 `main`、压缩包路径及运行文件；备份数据、用副本试运行，启用新版并检查健康状态。

GitHub 构建的是网页和独立 Node 运行文件；平板不需要 `npm ci`、Vue 构建工具或 `node_modules`。

`dist/` 是生成目录，不提交。发布包只包含启动器、`runtime.cjs`、前端构建文件和发布清单。源代码中的 `server.cjs` 优先加载 `backend/`；发布目录没有该源码目录，加载独立 `runtime.cjs`。

网页发布不代表 APK 已更新。前端热更新不能新增安卓权限。静态资源使用带内容哈希的文件名；HTML 不缓存。部署会先放置新资源、重启并验证后端，再切换 HTML，保留原资源供已打开的页面使用。

## 安卓打包与自动更新

沿用仓库 `android/build.ps1`，需要 JDK、Android SDK Platform 33、Build-Tools 33.0.2。执行时可显式传 `-JavaHome`、`-SdkRoot`。

修改安卓时递增 `AndroidManifest.xml` 的 `versionCode` 和 `versionName`，构建脚本会生成对应 `public/app-version.json`。必须使用原签名；不同签名不能覆盖安装。签名文件留在维护者本机，不上传仓库，不交给 GitHub 普通构建任务。

将构建出的 APK 以 `women-ledger-版本.apk` 命名，作为资产附加到同一个 GitHub Release。平板检查器发现新安卓版本而缺少 APK 时等待，不提前部署一个要求用户下载不存在安装包的版本。原有 APK 已在平板下载目录时可以复用。

App 0.3.2 及以上会在启动时检查版本、提示更新、下载并交给安卓安装界面。安卓仍要求用户确认；首次可能需要允许本 App 安装未知应用。更新后保留应用数据。网络不可用时不会把现有 App 锁死。文件保存能力需要 0.4.0。

## 运行、日志与回退

平板运行目录 `~/women-ledger`，数据在 `data/ledger.sqlite`；DSH 凭证在私有 `data/dsh-speech-cookie.txt`。云服务器为 HTTPS 与平板反向隧道入口，保留现有服务配置。

服务端错误日志：`data/logs/errors.jsonl`，自动限制文件大小，只记录时间、请求编号、路由、错误码和错误类型，不记录账本文字、密码、Cookie 或录音。前端设置页可导出最近的脱敏故障信息。

部署检查器日志：`release-updater.log`，已部署状态：`release-updater-state.json`，发布前备份：`data/backups/`，旧代码：`release-updater-work/`。这些仍在平板本机，不等于异地备份。

启用失败时尝试回退旧代码，不自动恢复旧数据库，以免覆盖发布期间已经写入的内容。失败提交暂停重复部署，人工检查后再发布修复提交。数据库回退必须停服、另外保留当前完整数据，再用副本验证恢复；不可直接覆盖。

首次从 v1 迁移需要维护者安装新版发布检查器 `dist/release-updater.cjs`，保留原有 SSH 和私有配置。以后网站发布按 Release 构建产物执行。部署检查器本身的升级仍应由维护者单独验证，不在普通页面发布中自动执行新的运维程序。
