# 我们：双人时间账本

在原单文件版基础上拆分前端，使用 Node.js 24 和 SQLite 保存双人账本。原始文件保存在 `原始页面.html`，不覆盖原文件。服务运行只依赖 Node.js 标准库，开发测试需要安装 npm 依赖。

## 项目结构

- `public/`：手机网页、样式、交互与同步代码。`original.js` 保留了原设计的大部分界面逻辑。
- `server.cjs`：Node.js HTTP 接口、身份验证、SQLite 持久化、同步与积分处理。
- `android/`：Android WebView 外壳、目标本机通知和自动打包脚本。
- `test/`：接口、账号、同步和浏览器测试；`docs/`：当前产品规划。
- `原始页面.html`：保留的原始单文件页面，日常修改以 `public/` 为准。

## 数据与使用边界

- 支持注册并邀请另一位成员，原有两个账号保留；各双人空间的数据隔离。新记录和目标可设置仅自己或双方可见；旧记录没有可见性字段时仍按共享处理。
- 另一端在页面空闲时定期检查更新，不是实时推送。不同记录的修改可以基于共同版本合并；同一字段冲突或基础版本过期时停止写入并提示下载未同步内容。下载的文件不能无条件导入。
- 每个目标可配置每次打卡积分；新记录关联目标时由服务端发分。奖励或愿望需设置正整数价格，由兑换者自己的余额支付。修改或删除已发分记录时，如果会造成余额不足，服务器会拒绝保存。
- 服务器保存最近 100 个历史版本和本机最多 14 份每日 SQLite 备份，它们不是异地备份。复制备份到另一台设备或可信加密存储，定期验证恢复。
- 浏览器暂存尚未同步的更改。浏览器数据可能被清理；冲突或断网时请尽快导出。共享电脑上的浏览器缓存也可能包含未同步内容。
- 她原来浏览器里的本地数据不会自动迁移。先从原网页导出 JSON，首次通过第一位成员账户使用“导入备份”。导入会整体替换已有共享账本，执行前先导出当前账本并确认归属。

## 首次本机运行

要求 Node.js 24 或以上，确认使用的是包含 `node:sqlite` 的官方版本。下面会在项目的 `data/` 目录创建独立的本机数据库，不会连接线上数据：

```sh
node server.cjs
```

浏览器打开 `http://127.0.0.1:18763`，注册第一个账号，并通过页面的邀请链接注册第二个账号。密码至少 12 字符。默认只监听本机。`node server.cjs setup` 是兼容原有第一、第二成员账号的可选方式，账户已存在时不会覆盖。修改原版账号密码：

```sh
node server.cjs passwd me
node server.cjs passwd him
```

修改密码会退出该成员的所有会话。

## 备份

运行时每天第一次启动、以及持续运行时每 24 小时尝试一次备份。使用 SQLite 在线备份 API 生成一致的数据库副本。失败会记录在服务日志，不能假定已经备份成功。数据库包含个人数据和密码哈希，不要放入可公开访问的目录。

另外手动生成一个不存在的备份文件：

```sh
node server.cjs backup /绝对路径/新的备份文件.sqlite
```

恢复前停止服务，先完整保留旧数据目录；另建一个空目录，将备份文件复制为其中的 `ledger.sqlite`，并通过 `WOMEN_DATA_DIR` 指向新目录启动。先验证内容和账户，再决定如何处理旧目录。备份恢复同时恢复当时的账户和会话状态。不要只复制正在运行的主数据库文件，也不要删除运行中的 WAL 文件。

## 公网部署前

本版本默认本机访问，不具备公网入口。正式启用必须先完成域名与 HTTPS 证书、反向代理、受保护的平板到云端连接、自动重启、独立备份以及真实手机测试。HTTPS 反向代理应保留原始 Host；使用 HTTPS 时设置 `WOMEN_SECURE_COOKIE=1`。不要直接把后端、SQLite 或调试接口暴露到公网。共享账本属于私人数据；先确认稳定性和备份，再录入重要内容。

同步使用历史快照进行三方合并，并非完整的实时协同；涉及顺序调整、同字段冲突或历史版本过期时仍可能需要人工处理。2MB 单次账本数据上限包括头像；不适合存储大量照片。新注册、邀请、私密记录和合并逻辑尚未完成独立公网安全审计和生产迁移验证。

## Android 测试包

Windows 自动打包需要 JDK 11、Android SDK Platform 33 和 Build-Tools 33.0.2。可用 Android Studio 的 SDK Manager 安装后两项，并设置 `JAVA_HOME` 和 `ANDROID_SDK_ROOT`；也可以直接向脚本指定路径：

```powershell
powershell -ExecutionPolicy Bypass -File android/build.ps1 -JavaHome 'C:\path\to\jdk-11' -SdkRoot 'C:\path\to\Android\Sdk'
```

成功后文件位于 `android/build/women-ledger-debug.apk`。脚本使用 `%LOCALAPPDATA%/women-ledger/debug.keystore`，不存在时自动创建。各开发者的测试签名通常不同：**不同签名的 APK 不能覆盖安装已存在的同包名应用**；卸载会删除该应用本机数据，处理前应先备份和同步。正式发布需单独、安全保管的发布签名，密钥不得提交仓库。

该 WebView 外壳固定打开 `https://tn.yidiangames.cn/`，所以默认连接真实线上账本，而非本机代码。仅改本地网站或重新打包不会改变线上网站。开发时优先在本机浏览器使用测试账号；如需让 Android 包连接测试站点，应在自己的分支中同时修改 `MainActivity.java` 中的网站地址、允许的主机及消息通道目标，以及 `AndroidManifest.xml` 的链接主机，并使用自己控制的 HTTPS 测试服务。未明确授权时不要在生产站点创建测试数据或部署。

测试包不具备离线服务；当前备份导出请使用手机浏览器。

0.3.0 起，故事接龙可点麦克风录音，再点一次结束；达到语音服务的时长或大小上限时自动结束，最长三分钟。文字只填入草稿，需用户确认发布。安卓 App 首次使用需授予麦克风权限；浏览器也需授权。手机将音频发送到账本后端，再转发至已配对的笔记本 DSH 进行识别；笔记本或其隧道不在线时不能使用。录音不保存到账本。配置文件默认位于服务器私有数据目录的 `dsh-speech-cookie.txt`，也可用 `WOMEN_DSH_COOKIE_FILE` 指定，严禁提交或公开该凭证。反向代理需要单独允许 `/api/speech/transcribe` 至少 8 MiB 的请求体，其他接口保留原有上限。服务端向 DSH 查询真实时长和大小上限，取不超过三分钟的值。

0.2.0 起，目标可选每天固定时间提醒。用户在 Android App 中登录并同步目标后，App 将该账号的提醒登记到设备；清空时间或结束目标会取消，主动退出登录会清理当前账号的本机提醒。Android 13 及以上需要允许通知，Android 12 及以上若要求准时可能还需授予“闹钟和提醒”权限。手机系统限制、强行停止应用等可能影响提醒；设备重启后 App 会尝试恢复。另一台设备修改提醒后，需要本机再次打开 App 并同步。普通浏览器中保存时间不会自动获得此 Android 本机提醒。

## 测试

运行 `npm ci` 安装锁定版本的开发测试依赖，再运行 `npx playwright install chromium` 安装测试浏览器。使用 Node.js 24 或以上执行 `npm test`，覆盖账号、鉴权、空间隔离、私人记录、积分、冲突及浏览器操作。测试使用独立临时数据库，不应使用生产数据库。这不是对所有实体设备或生产域名的验收。

## 发布网站

平板上的 `ops/release-updater.cjs` 独立运行，每五分钟检查一次本仓库 GitHub 的最新正式 Release；普通推送、草稿和预发布不会触发部署。只有正式版本所指的提交属于 `main` 历史，更新程序才会接受。仓库协作者的发布权限也意味着可以触发生产部署。

发布前在独立测试数据库中运行 `npm ci` 和 `npm test`，确认代码已合并并推送到 `main`。然后在 GitHub 的 Releases 页面创建正式 Release，标签指向准备上线的 `main` 提交，选择 Publish release；不要勾选预发布。部署不需要她的电脑连接服务器或配置服务器 SSH 密钥。部署有最多约五分钟检查延迟，前提是平板运行且可以访问 GitHub。

更新程序会校验脚本语法、在线备份 SQLite 并检查完整性，在备份的独立副本上试启动，再备份旧代码和部署；后端变动时由现有监督程序重启服务。运行日志在平板 `~/women-ledger/release-updater.log`，状态在 `release-updater-state.json`；备份在平板本机，不是异地备份。发生部署失败时程序尝试恢复旧代码并停止重复部署该提交；数据库不会自动回滚，以免覆盖部署期间写入的数据，必须人工检查日志和备份。当前检查不能代替正式发布前的完整测试。更新程序本身需要单独维护，不会自动替换自己。

此流程只部署网页和服务端，**不会构建或发布 Android APK**。网页修改后重开 App 即可；安卓原生代码、权限或资源变化仍需构建并分发签名一致的 APK。
