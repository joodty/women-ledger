# 我们：双人时间账本

在原单文件版基础上拆分前端，使用 Node.js 24 和 SQLite 保存一份两人共享的账本。原始文件保存在 `原始页面.html`，不覆盖原文件。Node 标准库运行，无需 npm 安装依赖。

## 数据与使用边界

- 两个成员分别用密码登录；所有账本记录都对两位成员可见。原型中的情侣码不用于身份验证，也没有单独的私密记录或服务端可见性开关。
- 一方保存后另一方刷新获取最新内容，不是实时推送。写入按整个账本版本比较，冲突时停止写入并提示下载未同步内容，不会自动合并；下载的文件不能无条件导入，否则会替换对方的数据。
- 原设计中的积分分值和部分结算仍是“待定”占位；没有把它们当作完整积分系统。无离线自动合并。
- 服务器保存最近 100 个历史版本和本机最多 14 份每日 SQLite 备份，它们不是异地备份。复制备份到另一台设备或可信加密存储，定期验证恢复。
- 浏览器暂存尚未同步的更改。浏览器数据可能被清理；冲突或断网时请尽快导出。共享电脑上的浏览器缓存也可能包含未同步内容。
- 她原来浏览器里的本地数据不会自动迁移。先从原网页导出 JSON，首次通过第一位成员账户使用“导入备份”。导入会整体替换已有共享账本，执行前先导出当前账本并确认归属。

## 首次本机运行

要求 Node.js 24 或以上，确认使用的是包含 `node:sqlite` 的官方版本。Termux 中请先安装并更新 Node.js LTS 和基础包。以下在项目目录执行：

```sh
node server.cjs setup
node server.cjs
```

首次设置会交互创建第一、第二成员的密码；至少 12 字符，输入不回显。保管好密码。默认只监听本机 `127.0.0.1:18763`。账户已存在时 setup 不会覆盖。修改密码：

```sh
node server.cjs passwd me
node server.cjs passwd him
```

修改密码会退出该成员的所有会话。

## 备份

运行时每天第一次启动、以及持续运行时每 24 小时尝试一次备份。使用 SQLite 在线备份 API 生成一致的数据库副本。失败会记录在服务日志，不能假定已经备份成功。数据库包含个人数据和密码哈希，不要放入可公开访问的目录。

另外手动生成一个不存在的备份文件：

```sh
node server.cjs backup /绝对路径/新的备份文件.sqlite
```

恢复前停止服务，先完整保留旧数据目录；另建一个空目录，将备份文件复制为其中的 `ledger.sqlite`，并通过 `WOMEN_DATA_DIR` 指向新目录启动。先验证内容和账户，再决定如何处理旧目录。备份恢复同时恢复当时的账户和会话状态。不要只复制正在运行的主数据库文件，也不要删除运行中的 WAL 文件。

## 公网部署前

本版本默认本机访问，不具备公网入口。正式启用必须先完成域名与 HTTPS 证书、反向代理、受保护的平板到云端连接、自动重启、独立备份以及真实手机测试。HTTPS 反向代理应保留原始 Host；使用 HTTPS 时设置 `WOMEN_SECURE_COOKIE=1`。不要直接把后端、SQLite 或调试接口暴露到公网。共享账本属于私人数据；先确认稳定性和备份，再录入重要内容。

原子版本冲突策略按整份账本判断；两端同时编辑不同记录也可能触发冲突，后续可升级为逐条合并。2MB 单次账本数据上限包括头像；不适合存储大量照片。当前会话管理和限制为两人轻量场景，尚未完成公网安全审计。

## 测试

运行 `npm install` 安装开发测试依赖，再运行 `npx playwright install chromium` 安装测试浏览器。`npm test` 会验证登录、鉴权、共享、冲突、备份、重启，以及手机和桌面视口下的同步、离线重试和历史恢复。这不是移动设备实机或生产域名测试。
